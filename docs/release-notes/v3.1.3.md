# v3.1.3

Las actualizaciones ya no se rinden al primer tropiezo y, si algo falla, ahora explican el motivo.

## Corregido

- **La descarga se abandonaba tras diez segundos sin recibir bytes.** Es un plazo demasiado estricto para una transferencia TLS en un dispositivo que también está pesando, sirviendo la interfaz web y comunicándose con la nube. Una transferencia que podría haberse recuperado se informaba como actualización fallida. El plazo ahora es de treinta segundos.
- **Una imagen fallida se vuelve a intentar una vez automáticamente.** Los bloqueos observados hasta ahora eran transitorios. Pedir a alguien que vuelva a iniciar manualmente una actualización de dos minutos cuando la báscula puede reintentarlo en dos segundos es una mala solución.
- **Si se interrumpe la descarga, ahora se indica en qué punto ocurrió y cuánta memoria quedaba.** En el único fallo capturado antes de este cambio, la memoria libre había bajado a unos 31 KB, un indicio útil que solo se pudo observar porque había un cable serie conectado.

## Problemas conocidos

- Todavía no se ha demostrado la causa de los bloqueos. Las pruebas apuntan a presión de memoria durante el establecimiento TLS y la transferencia, no a la red. El momento más fiable para actualizar sigue siendo poco después de reiniciar, cuando la memoria está menos fragmentada.

## Actualización

Actualiza por el aire desde **Ajustes > Actualización**, o por USB con `bash scripts/flash.sh --fs`. Ambos métodos conservan las credenciales Wi-Fi, la sesión de TigerTag y la calibración.
